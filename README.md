# 出面確認台帳

グリュック合同会社の現場出面を、日付・地域・現場ごとに確認する台帳です。出勤・休み・欠勤・休暇・未入力・移動を照合し、重複を除いた実人数、出勤率、必要人数との差、同日に2現場へ出ている人を見ます。閲覧も編集もログインが必要です。

画面はチャコールブラックにセーフティオレンジです。パソコンは1画面のダッシュボード、スマホは大きな出勤数と下部のタブで操作します。

## 起動

```bash
npm install
npm run seed
npm run dev
```

ブラウザで http://127.0.0.1:43123 を開きます。

`npm run seed` は台帳が空のときだけデモデータを入れます。入れ直すときは `npm run seed -- --force` です。デモの氏名・現場名は架空です。実在の作業員名簿はリポジトリに入れていません。

デモ用ログイン（本番では削除してください）:

| 権限 | メール | パスワード |
| --- | --- | --- |
| 管理者 | admin@gluck.example | Gluck-Demo-2026 |
| 編集 | editor@gluck.example | Gluck-Demo-2026 |
| 閲覧 | viewer@gluck.example | Gluck-Demo-2026 |

## 本番の初期ユーザー

デモを使わない場合は、サーバー上で利用者を作ります。

```bash
npm run user:create -- --email you@example.jp --name 山田 --password '10文字以上のパスワード' --role admin
```

`--role` は `admin`（取込と利用者管理もできる）、`editor`（訂正できる）、`viewer`（見るだけ）です。

## 使い方

- 上部（スマホは日付バー）で対象日を前後に動かせます。地域と現場で集計が変わります。
- 全体人数は名簿の行数ではなく、空白を除いた氏名でまとめた実人数です。同じ人が同日に2現場で出勤になっていると、人数は1人のまま警告を出します。
- 会社一括の行はグループ人工として別扱いで、人数には入れません。`3時間` や `残業2` は出勤人数に入れ、数値の人工には足しません。`移動` は出勤にしません。
- 現場の行を開くと作業員一覧です。編集権限があると「訂正・確認を登録」から、勤務・所属・必要人数・メモを保存できます。根拠と確認日が必須です。
- 右上のダウンロード、または実績・レポートの「作業員CSV」で書き出せます。
- アラートに、要員不足・2現場出勤・未入力・対応待ちが出ます。
- 印刷は実績・レポートの「印刷」から、紙向けの白地です。

## データの取り込み

設定（管理者のみ）から、次のどちらかを選べます。

- 現行サイトの `/api/state` と同じ JSON（`ledger` と `events`）
- 横持のCSV。1行目は `案件,地域,作業員,所属,単位,1,2,3,…`。セルは `1` `出勤` `休み` `欠勤` `休暇` `移動` `3時間` など。単位が `会社一括` の行はグループ人工です。見本は `samples/sheet-sample.csv`、デモ一式は `npm run seed` が書く `samples/demo-state.json` です。

台帳の中身は月次スプレッドシートの形に合わせています。日ごとの記号は `val` 表と名簿行の文字で保持し、判定はそこから計算します。本物のシートへの接続手順は、下の「スプレッドシートとつなぐ」にあります。

人数のルールは現行の判定（確度が確定の出勤だけを稼働と数える、未確認が残ると不足は未確定）を守ったうえで、表示の基本を実人数にしています。

## 本番をどこに置くか

まだアカウントは作っていません。2026年11月19日に各社の料金ページを見た結論です。社員10人、ログイン必須、5分ごとのシート同期、台帳を消さない、できれば無料、という条件です。

今のアプリは Node.js の Next.js で、台帳はサーバーの中の SQLite ファイル（`data/gluck.sqlite`）です。ファイルが消える置き場所では、ログインも出面も消えます。5分同期は、アプリが動いているあいだ自分で繰り返します。アプリがスリープすると、その繰り返しは止まります。

### おすすめ

**Render の月7ドルのサーバー（メモリ512MB）に、1GBの永続ディスク（月0.25ドル）を足す。** 合計は月およそ7.25ドルです。リージョンはシンガポールにしてください。公式の地域はオレゴン、オハイオ、バージニア、フランクフルト、シンガポールで、東京はありません。

この組み合わせにした理由は次のとおりです。

- スリープしません。無料枠は15分アクセスがないと止まり、次の表示まで約1分かかります。出面の確認には向きません。
- ディスクを残せるので、今の SQLite をほぼそのまま使えます。データベースの作り替えは不要です。
- 5分同期は、サーバーが起きているあいだ今の仕組みのまま動きます。別のタイマーは要りません。
- HTTPS は Render が付けます。`COOKIE_SECURE=1` にします。
- 会社の業務に使えます。無料のサーバーは公式に「本番アプリケーションには使わないでください」と書いてあります。

ワークスペースの無料プラン（Hobby）は「個人の試作」と書かれています。サーバー代の7ドルとは別です。複数人で管理画面を分けたいときは、ワークスペースの Pro が月25ドル追加になります。ひとりが設定するだけなら、Hobby のワークスペースに月7ドルのサーバーを足す形で足ります。

### 無料にこだわると

全部の条件を公式の無料枠だけで満たす置き場所はありません。どうしても0円にするなら、データベースだけ [Turso の無料](https://turso.tech/pricing)（カード不要、5GB、月5億行の読み取り、月1,000万行の書き込み、上限を超えると止まる）に移し、画面は Render の無料サーバーに置きます。ただし次の欠点があります。

- Render の無料は15分でスリープし、ディスクは再起動のたびに消えます。SQLite は使えません。
- 5分ごとに外から起こすと、31日の月は約744時間になり、無料の750時間の上限にほぼ張り付きます。超えるとその月は止まります。
- アプリのデータベース接続を、ファイルの SQLite から Turso 用に書き換える作業が必要です。

## 配置

常時起動する Node.js 22 のサーバーを想定しています。SQLite は `data/gluck.sqlite` にできます。このフォルダを消すと台帳もログインも消えるので、ディスクを残してください。ファイルが消えるホスティングには向きません。

```bash
npm ci
npm run build
COOKIE_SECURE=1 npm start
```

社内ネットワークのHTTPだけで動かすときは `COOKIE_SECURE=0` にしてください。HTTPSの前に置く場合は、そのままでクッキーが Secure になります。

Dockerの例:

```bash
docker build -t gluck-demen .
docker run --rm -p 43123:43123 -v gluck-data:/app/data -e COOKIE_SECURE=0 gluck-demen
```

公開前にやること:

1. `npm run user:create` で本番の管理者を作る
2. デモの3人を設定画面から削除する
3. `data/` をバックアップできる場所に置く
4. HTTPSにして `COOKIE_SECURE=1` にする
5. 現行の state JSON を管理者で取り込む（画面の外には出さない）

## スプレッドシートとつなぐ

出面の元データは、月ごとのGoogleスプレッドシートです。タブが現場、列が作業員、行が日付です。このアプリはシートを読むだけで、シート自体は書き換えません。

このパソコンでは本物のGoogleに接続できないため、見本用の模擬シート（ダミーの氏名）で動いています。本物につなぐときは、下の手順を一度だけ行います。

### 1. ロボット用のアカウントを作る

1. パソコンで [Google Cloud コンソール](https://console.cloud.google.com/) を開きます。
2. 上の方のプロジェクト名をクリックし、「新しいプロジェクト」を作ります。名前は「出面台帳」で構いません。
3. 左のメニュー（三本線）から「APIとサービス」→「ライブラリ」を開きます。
4. 検索欄に「Google Sheets API」と入れ、開いて「有効にする」を押します。
5. 「APIとサービス」→「認証情報」を開きます。
6. 「認証情報を作成」→「サービスアカウント」を選びます。
7. 名前は「出面を読む係」などで進め、作成します。
8. できたアカウントの名前をクリックし、「鍵」タブ →「鍵を追加」→「新しい鍵を作成」→ JSON → 作成。ファイルがダウンロードされます。
9. その画面に書いてあるメールアドレス（`...@...iam.gserviceaccount.com`）をコピーします。

### 2. シートをそのメールアドレスに共有する

1. 出面のスプレッドシートを開きます。
2. 右上の「共有」を押します。
3. コピーしたメールアドレスを貼り付けます。
4. 権限は「閲覧者」のままにします。編集者にしなくて大丈夫です。
5. 送信します。月が変わって新しいシートを作ったら、同じメールアドレスへもう一度共有します。

### 3. サーバーに鍵を渡す

ダウンロードしたJSONファイルを、誰にも見られない場所に置きます。中身を全部コピーして、サーバーの環境変数にします。

```bash
GOOGLE_SERVICE_ACCOUNT_JSON='ここにJSONを1行で貼る'
```

社内のHTTPだけで動かすときは、あわせて `COOKIE_SECURE=0` にします。

### 4. 画面からシートを登録する

1. 管理者でログインします。
2. 「設定」を開きます。
3. 「スプレッドシート同期」に、シートのURLを貼ります。ブラウザのアドレスバーのURLで大丈夫です。
4. 月を選び、「登録して同期」を押します。
5. タブ名と、サイトに出す案件名が違うときは、表の中を書き換えます。例: ルミック・ラピダス → ラピダス・北海道、ルミック・青森 → ルミック・六ヶ所、三電社/青森 → 三電社・青森、レックス → レックス枚方案件、佐々木 → 佐々木電業。
6. 初めて見たタブは「新着」と出ます。取り込むものだけチェックを付け、「対応表を保存」のあと「今すぐ同期」を押します。
7. ひな形タブと、前の締め期間（例: 佐々木9/21～10/20）は自動で外します。佐々木10/21～11/20 のように月をまたぐタブは、11月分は11月、10月分は10月の台帳に分かれます。

あとは既定で5分ごとに読みにいきます。間隔は設定画面で変えられます。画面上の「更新」は、最後に同期した時刻と「要確認」の件数です。

シートの空欄は休みとは決めません。読めないセル、合計のずれ、単価が1円ずつ増えている列、単価が空なのに出面がある人、当日だれも記入されていない現場、同日に2現場へ出ている人は、アラートと同期ログに出します。画面で直した内容は、次の同期でも残ります。シートと食い違う人には「差分あり」と出ます。
