# 出面確認台帳

グリュック合同会社の現場出面を、日付・地域・現場ごとに確認する台帳です。出勤・休み・欠勤・休暇・未入力・移動を照合し、重複を除いた実人数、出勤率、必要人数との差、同日に2現場へ出ている人を見ます。閲覧も編集もログインが必要です。

画面はチャコールブラックにセーフティオレンジです。パソコンは1画面のダッシュボード、スマホは大きな出勤数と下部のタブで操作します。

## 起動

```bash
npm install
npm run seed
npm run dev
```

ブラウザで http://127.0.0.1:43123 を開きます。

`npm run seed` は台帳が空のときだけデモデータを入れます。入れ直すときは `npm run seed -- --force` です。デモの氏名・現場名は架空です。実在の作業員名簿はリポジトリに入れていません。

デモ用ログイン（本番では削除してください）:

| 権限 | メール | パスワード |
| --- | --- | --- |
| 管理者 | admin@gluck.example | Gluck-Demo-2026 |
| 編集 | editor@gluck.example | Gluck-Demo-2026 |
| 閲覧 | viewer@gluck.example | Gluck-Demo-2026 |

## 本番の初期ユーザー

デモを使わない場合は、サーバー上で利用者を作ります。

```bash
npm run user:create -- --email you@example.jp --name 山田 --password '10文字以上のパスワード' --role admin
```

`--role` は `admin`（取込と利用者管理もできる）、`editor`（訂正できる）、`viewer`（見るだけ）です。

## 使い方

- 上部（スマホは日付バー）で対象日を前後に動かせます。地域と現場で集計が変わります。
- 全体人数は名簿の行数ではなく、空白を除いた氏名でまとめた実人数です。同じ人が同日に2現場で出勤になっていると、人数は1人のまま警告を出します。
- 会社一括の行はグループ人工として別扱いで、人数には入れません。`3時間` や `残業2` は出勤人数に入れ、数値の人工には足しません。`移動` は出勤にしません。
- 現場の行を開くと作業員一覧です。編集権限があると「訂正・確認を登録」から、勤務・所属・必要人数・メモを保存できます。根拠と確認日が必須です。
- 右上のダウンロード、または実績・レポートの「作業員CSV」で書き出せます。
- アラートに、要員不足・2現場出勤・未入力・対応待ちが出ます。
- 印刷は実績・レポートの「印刷」から、紙向けの白地です。

## データの取り込み

設定（管理者のみ）から、次のどちらかを選べます。

- 現行サイトの `/api/state` と同じ JSON（`ledger` と `events`）
- 横持のCSV。1行目は `案件,地域,作業員,所属,単位,1,2,3,…`。セルは `1` `出勤` `休み` `欠勤` `休暇` `移動` `3時間` など。単位が `会社一括` の行はグループ人工です。見本は `samples/sheet-sample.csv`、デモ一式は `npm run seed` が書く `samples/demo-state.json` です。

台帳の中身はスプレッドシート「2026年11月　出面」の正規化です。日ごとの記号は `val` 表と名簿行の文字で保持し、判定はそこから計算します。タブ名は `meta.sheet` と案件の `sheetTab` に載せられるので、あとからシート連携を足しても形は衝突しません。GoogleスプレッドシートAPIへの直接接続はまだありません。

人数のルールは現行の判定（確度が確定の出勤だけを稼働と数える、未確認が残ると不足は未確定）を守ったうえで、表示の基本を実人数にしています。

## 配置

常時起動するNode.js 22のサーバーを想定しています。SQLiteは `data/gluck.sqlite` にできます。このフォルダを消すと台帳もログインも消えるので、ディスクを残してください。サーバーレス（ファイルが消えるホスティング）には向きません。

```bash
npm ci
npm run build
COOKIE_SECURE=1 npm start
```

社内ネットワークのHTTPだけで動かすときは `COOKIE_SECURE=0` にしてください。HTTPSの前に置く場合は、そのままでクッキーが Secure になります。

Dockerの例:

```bash
docker build -t gluck-demen .
docker run --rm -p 43123:43123 -v gluck-data:/app/data -e COOKIE_SECURE=0 gluck-demen
```

公開前にやること:

1. `npm run user:create` で本番の管理者を作る
2. デモの3人を設定画面から削除する
3. `data/` をバックアップできる場所に置く
4. HTTPSにして `COOKIE_SECURE=1` にする
5. 現行の state JSON を管理者で取り込む（画面の外には出さない）
